# 发布首日总结模板（老板认可版）

参考页：`【2026/10/23】Kimi K3.1 Pro 发布首日总结`（飞书 Wiki，2026-10-25 用户确认为「老板喜欢的最终版」）。参考 token 只说明模板来源，不能当作写入或校验目标。

适用：用户要「发布首日总结 / 首日快报 / 竞品发布快报」，读者是老板和业务负责人，要求一屏拿到结论。它和 `CHILD-DOC-TEMPLATE.md`（GPT-5.5 版 Wiki 子文档、四列证据墙、validator 门禁）是两种交付物：用户只要首日总结时用本模板，不强制 A/B/C 同步和四列证据墙；用户要求同步汇总页/Sheet 时仍走原流程。

## 写作原则

- **结论前置、口语短句**：每条一句话，能被直接转述，例如「sonnet 价格，opus 效果」「国模第一」「价格 ×2，速度 ×2」。不写成段论证。
- **截图优先**：榜单、价格页、社媒帖、群聊直接贴图，文字只写判断；图片说明可以放在评论里，不必配图注。
- **少标注**：不逐条写置信度标签、抓取时间戳、方法口径说明；来源用行内链接或表格「来源」列即可。只有关键争议数字才写口径。
- **内部视角**：MiniMax 内部 Arena、Vela 等自测、飞书用户群/竞品群反馈是这份文档区别于媒体稿的核心。Agent 拿不到时，在对应位置留出标题并在回复里请用户补截图，不编造。
- **对我方只写一两句**，落到具体产品（如「对 Flash 压力小，对 Pro 压力大」）。
- 不单列：开源进度、用户激励、技术博客附录、头部 KOL 名单。精华并入 TL;DR 或社区表。

## 页面骨架

标题：`【YYYY/MM/DD】<模型> 发布首日总结`（日期用厂商发布日）。

### 0. 顶部 📌 Callout

1. `Blog:` 官方博客链接（加粗）。
2. `TL;DR` 约 6 条 bullet：基座/参数变化；独立榜单分数与名次（AA、开源第几）；国模排名（含内外 Arena）；token 效率；一句话定位；口碑正负 + 主要吐槽点（加粗）。
3. 博客要点编号列表（约 5 条，每条加粗标题 + 1–3 个子 bullet）：定位、技术叙事、主打 Benchmark 及叙事口径（如「接近或超过」）、垂直场景（每个配跑分 + Demo）、官方特别着墨的章节（如安全）。

TL;DR 和正文的数字必须同一口径（如 TB4 博客 65.7% 与其他来源 67.2% 不能混用而不注明），写完逐个对一遍。

### 1. 截图墙（callout 之后、H1 之前）

- 一行「发布时间：北京时间 YYYY-MM-DD HH:MM」。
- 2–4 组 grid：AA 指数、Arena（如 `arena.ai/leaderboard/code/webdev`）、Agent 榜单、内部 Arena。截图不配正文，说明可写评论。
- arena.ai 有 Cloudflare，web_fetch 403；用内置浏览器打开后截图，并把窗口放宽保证分数列完整。

### 2. H1「官方叙事逻辑」

两列 grid：左列「疑似 <厂商> 内部定的 key point」4–6 条编号（产品替代、能力卖点、性价比、开源/本地部署、中美差距、算力叙事等，按实际推测）；右列放最能代表官方叙事的社媒帖截图。

### 3. H2「一、官方宣发拆解」

开头一句概括打法链路，例如「泄露预热 → 匿名竞技场试水 → 先导片 → 深夜博客 + X 首发 → 第三方榜单当晚背书」。

- H3 `1. 发布节奏`：表格 时间 / 事件 / 类型（【官方】【社区】【三方】+ 泄露/预热）/ 来源；表后 2 条 bullet：首发渠道、是否倒计时/泄露节奏。
- H3 `2. 核心叙事`：新概念、媒体二次放大口径（标明非官方原话）、资本背景。
- H3 `3. Benchmark 选择`：两列 grid，左列「判断」（对比对象、真实强项与短板）+「方法口径」（harness、内部榜数量），右列官方跑分表截图。
- H3 `4. Demo 与素材`：按场景分 H4（如 ① 游戏 ② 3D ③ 交互网页 ④ 金融 ⑤ 长程 Agent，标题写案例数和素材形式）；每个案例一列 grid，列内「加粗案例名：一句说明」+ 官方视频（Preview 播放器）或封面图；可交互页面给链接，可下载交付物给下载链接；同步上线的产品功能放在相关场景旁。
- H3 `证明刷榜的证据？`（有争议时）：截图 + 一句判断。

### 4. H2「二、定价」

官方价格页截图、对比截图若干，然后两条 bullet：
- **意图**：价位对标谁、抢谁的预算。
- **对我方**：落到具体产品线的压力判断，含倍数（如「输入约为其 1/13」）。

Highspeed / 批处理等变体的价格与速度关系可一句话带过（如「价格 ×2，速度 ×2；OR 口径 36 tps，国内约 50」）。

### 5. H2「三、社区首轮回应」

- 先一段**判断**，带数字（如 HN 72 条有效顶层评论：兴奋 37.5% / 观望 31.9% / 质疑 30.6%），并点出海外与国内的分歧。
- H3 `海外`：表格 平台 / 原声 / 作者身份（标注利益相关）/ 互动量 / 时间 / 来源。
- H3 `国内`：一句总判断；**飞书用户群反馈（MiniMax 群 + 竞品群）** 按主题编号（价格与额度、速度、能力口碑、接入报障、推理深度、竞品借势），每条加粗主题 + 原话引号，配群聊截图 grid；再列「社媒」3–4 条带链接；最后「问题」小结：首轮实测翻车点、可用性问题、质疑与争议。

### 6. H2「四、宣发打法：值得借鉴 vs 暴露短板」

- **值得借鉴** 3 条：每条加粗一句话 + 证据（好转述的数字、主动讲取舍、视觉化 Demo 等）。
- **暴露的短板** 1–3 条：如 Day-0 生态、供应商单一。

## 写入与协作

- 用户会直接在飞书里改稿：之后只做定点 block 操作（`block_insert_after` / `block_replace` / `block_delete` / `str_replace`），禁止 `overwrite`；每次操作前用 `--detail with-ids` 重新拉取 block ID。用户删掉的章节不要加回。
- lark-cli markdown 写入时 `$` 写成 `\$`；视频用 `<figure view-type="Preview"><source path="@./v.mp4"/></figure>` 上传，复用已上传素材用 `<source token=…>` / `<img src=…>`。
- 回读全文和评论（`--detail full` 含 comments），评论里常有内部补充数据（自测分数、速度口径），写回复时一并汇报。
